# 随行定位 · 安卓蓝牙验证版

基于现有 Flutter 项目增加 Android 入口与 Kotlin iAP2 协议核心。1.2.7（构建 14）增加“首页 / 设置”独立底栏和关于页面，移除诊断入口与日志缓存；保留 1.2.6 的地点坐标解析：已有坐标直接选择，无坐标建议按地点 ID、完整地区地址补查；自动模式在高德无结果时也补查开放地图。保留用户已验证可用的安卓原生 Key、城市编辑窗口，以及中文页面、经典蓝牙 RFCOMM、认证和定位订阅。此 APK 用于用户安装验证，正式发布等待实测反馈。

最低 Android 8.0（API 26）；Android 12 以上按系统要求申请“附近设备／蓝牙连接”权限，Android 13 以上可另行允许连接通知。面向 Android 17 的实机兼容性由用户测试确认。本版不申请手机定位权限，不做蓝牙扫描，只读取已配对设备。

## 1.2.7 首页、设置与关于

- 底栏只有“首页”和“设置”。首页集中显示连接状态、目标位置和设备；设置集中管理搜索、本机蓝牙地址、连接通知与关于。
- 切换页面保留当前连接、设备选择、未应用坐标和滚动位置，不自动断开、连接或发送位置。活动会话期间禁止修改本机地址；正常断开后可修改并保存。
- 设置页可打开搜索配置，地图里仍提供快捷入口。Key 与城市继续使用已验证的原生编辑窗口。
- 两端共享“关于随行定位”，显示版本、项目名“ios定位”、原项目与实验身份来源的 GitHub 地址及开源署名；可打开或复制地址。自己的仓库尚未发布，不显示虚构地址。
- 移除输入诊断、复制日志、焦点记录与日志缓存；保留连接状态和错误提示。
- 创建自己的仓库后，构建时传入 `-ProjectGithubUrl 'https://github.com/你的用户名/仓库名'`，两端关于页即可显示项目地址。也可修改 `FlutterApp/lib/app_info.dart` 中的配置。原项目链接仍独立保留。

## 安装与测试

1. 安装同目录的测试 APK（使用测试签名）。
2. 先断开电脑端与该 iPhone 的定位连接。在安卓系统蓝牙设置中与 iPhone 配对，并确认两端配对请求。
3. 安卓打开“随行定位·蓝牙验证”，点击“读取已配对设备”，允许附近设备权限，选中 iPhone。
4. 切到“设置 → 本机蓝牙地址”，填写**安卓手机自己的真实蓝牙 MAC 地址**，格式为 `AA:BB:CC:DD:EE:FF`。通常位于“关于手机 → 详细信息与规格／状态信息 → 蓝牙地址”；蓝牙需处于开启状态。也可在 iPhone 已配对设备的详情中查看安卓设备地址（若该系统提供）。应用内“打开手机信息”可进入系统信息页，具体页面因系统而异。不要填 iPhone 地址，也不要填 Wi-Fi MAC 或系统占位值 `02:00:00:00:00:00`。点击“保存本机地址”后返回首页连接。
5. 返回“首页”，点击“连接所选 iPhone”。查看蓝牙、识别、认证、订阅四项状态。连接、协商中可以取消；失败后可重试。
6. 在“目标位置”点击“地图选点与搜索”。轻点地图选点，可双指缩放、用加减按钮缩放，或搜索地名、地址。选好后点击“选好并填入坐标”返回，再点击“应用并持续发送”。也可手动填写 WGS84 纬度、经度及海拔。打开地图、搜索、选点、返回本身均不发送新位置；海拔保留输入值。
7. 在 iPhone 地图查看实际效果，再修改一个新坐标并再次应用，观察当前坐标版本和提交计数，以及 iPhone 是否随之更新。
8. 完成后点击“断开连接”，或点击通知里的“断开连接”。停止发送不能保证 iPhone 立即恢复真实位置。

## 状态含义

“已提交”表示安卓协议层已接受定位报文进入发送流程，不表示 iPhone 已采用该位置。实际位置由用户在 iPhone 上确认。初次默认每秒发送一次，iPhone 若请求了单句周期则以请求周期为准。首页显示认证、订阅、提交计数及错误状态。

连接在前台服务中维持；可切到手机地图等其他应用。通知与会话唤醒锁仅在连接期间持有，断开、异常或服务销毁会释放。系统强行结束应用、从最近任务划掉本应用会停止连接；应用不会自行重新连接或自动应用坐标。小米／红米系统的电池管理是否允许长时间保持需实测。

用户已在当前手机组合上实测通过认证、订阅并实现定位；连续换点仍需要在 iPhone 上切换定位及 Wi-Fi。本次接入地图不改变蓝牙换点机制，也不代表全部 iOS 版本均已验证。

## 地图与搜索

### 1.2.6 地点坐标补查

- 搜索结果或输入联想已有合法坐标时，点击直接选中，不再强制读取详情，避免详情记录失效导致已有坐标无法使用。选择坐标不要求搜索服务继续可用。
- 无坐标建议保留省市区县、乡镇地址和行政区编码。点击后先按地点 ID 查详情；无详情或无 ID 时，带完整地区地址查地点，再用高德正向地理编码解析村名、街道、门牌。补查使用所选结果的地区信息，优先于当前地图中心和之前设置的城市。
- 同名地点返回多个候选时交由用户选择。地址解析显示服务返回的匹配级别，例如村庄、乡镇、区县、门牌号；近似地址和缺少地区校验信息的候选需核对后点击，不把区域代表点当作门牌精确点。
- 自动模式同时处理高德调用失败和高德无可用坐标两种情况，补查 Photon／OpenStreetMap；已有建议不会因可选补查失败而被清空。手动指定高德或开放地图时尊重所选服务，不自动切换。
- 推断地图所在城市、合并周边结果和补查地址属于可选步骤，失败不丢弃已取得的地点坐标。单次网络请求最多等待 5 秒，整次搜索／补查最多 30 秒；改词、取消、地图选点或离开页面取消旧请求。
- 所有来源仍统一为 WGS-84 后回填；不以地图中心或默认坐标代替未找到的地点。查不到时可关闭结果在地图上选点。搜索数据未收录的地名仍可能没有候选，不能保证任意名称都有准确地址数据。

本版由用户重点验证：之前无有效坐标的村名、同名村跨地区搜索、完整乡镇村地址，以及搜索后选点回填。离线 HTTP 检查仅验证请求、解析、兜底、取消和坐标转换，不能代表真实地图数据的覆盖程度。

### 1.2.5 默认使用原生编辑窗口

现在直接点 Key、优先城市输入框，或标题右侧的“编辑”，都会打开已验证的同一个安卓原生窗口。表单中的 Flutter 输入组件只显示草稿并排除焦点，不再尝试建立另一条键盘连接。可键入、粘贴、确认“填入”，也可取消或返回。Key 默认隐藏，可勾选显示；Key 编辑窗口禁止截图。填入只更新表单，仍需点击“保存设置”才存入本机；取消保留原值。

- 默认高德地图，可切换开放地图。高德底图选点自动转换到 WGS-84，切换底图保持所选地理位置不变。
- 首次没有已填坐标时，地图先展示上海区域；需手动选点才能确认，不自动应用默认位置。已有合法坐标时以当前输入为准。
- 页面提供返回、取消，搜索结果提供关闭，放大缩小与回到所选位置独立操作。地图加载失败可重试或切换底图。
- 连续输入至少两个字符后，短暂停顿会显示联想结果；中文输入法正在组合候选词时不请求。点击“搜索”或键盘搜索键可查找更完整的地点列表。改词、取消、返回或改为地图选点会取消旧请求，旧结果不会覆盖新关键词。
- “搜索设置”提供自动、高德、开放地图三种服务。自动模式下，填写高德 Web 服务 Key 后优先用高德，服务失败或无可用坐标时补查 Photon 并显示原因。未填写 Key 时用 Photon；指定高德时不跨服务补查。切换底图不会改变搜索服务。
- 高德 Key 需自行在高德开放平台创建“Web 服务”类型后填入。应用不内置公共搜索 Key。Key 使用 Android Keystore AES-GCM 加密保存在本机；清空后保存可删除。
- 可设置优先城市，或留空跟随地图区域。“优先当前地图附近”使用地图中心，不读取安卓真实位置。高德会参考地图所在城市、合并地点与 50 公里内的周边搜索，并保留同名精确匹配；Photon 使用地图中心偏置。跨城市搜索可输入城市加地名，或关闭附近优先。
- 结果显示区域、详细地址、地点分类（服务提供时）及距本次搜索地图中心的距离，方便区分同名地点。高德普通搜索每类获取 20 条，合并去重后最多显示 30 条；Photon 普通搜索请求 20 条，实际数量由服务决定。
- 点击已有坐标的地点直接选中；无坐标建议会依次补查 ID、完整地区地址和地址编码。地址匹配级别及同名候选供用户核对，不会以默认坐标应用。Photon 的国内详细地点覆盖仍有限，可配置高德或直接轻点地图。
- 搜索框也接受 `纬度,经度`（WGS-84），高德坐标可加 `gcj:` 前缀。搜索结果、手动坐标均需选中确认后回填，再显式应用。
- 地图和搜索需要网络。仅增加联网权限，不申请安卓手机定位权限，也不会读取安卓手机当前位置。

## 开发构建

入口：`FlutterApp/lib/main_android.dart`。原生核心：`FlutterApp/android/app/src/main/kotlin/cn/suixing/suixing_loc/`。

运行 `scripts/build-android-test.ps1`，可通过参数指定 Flutter、JDK、Android SDK、英文构建目录及输出目录。构建流程执行 Flutter 分析、无设备输入 Widget 测试、坐标检查、搜索离线 HTTP 集成检查、APK 编译、JVM 协议测试和 APK 签名验证，不安装应用、不启动模拟器、不连接设备。测试 APK 暂使用 Android 标准 debug 测试签名，不是正式发布证书。密钥与证书只在英文构建目录注入 APK，不写入源码目录；材料来源见《身份来源说明.md》。

源码中的协议帧、识别、NMEA、跳变策略逐项对照本项目 C# 实现移植。Android 权限和前台服务实现参考 Android 官方文档，RFCOMM 使用 iAP2 服务 UUID `00000000-deca-fade-deca-deafdecacafe`，没有使用通用串口 UUID。

静态编译与离线测试通过不等于真机认证通过。本次不运行真机、模拟器或 UI 验收。
